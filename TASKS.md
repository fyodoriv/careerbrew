- [ ] Hosted CI: reuse passed gate steps between hosted runs
  - **ID**: hosted-ci-step-cache
  - **Details**: `scripts/check.sh` already skips a step whose inputs passed before (read `scripts/check.sh` and `tests/unit/test_gate_cache.py` first to learn where the cache folder is and which variable moves it). On a runner that folder starts empty, so every run repeats every step. Steps. (1) Find the cache folder variable in `scripts/check.sh`. If the folder cannot be moved, add one variable for it, with a unit test. (2) In `.github/workflows/ci.yml`, before the gate step, add `actions/cache` with `path: ${{ runner.temp }}/gate-cache`, `key: gate-${{ matrix.os }}-${{ github.run_id }}-${{ github.run_attempt }}`, and `restore-keys: gate-${{ matrix.os }}-`. A cache entry cannot be changed, so each run saves a new entry and restores the newest one. Then export the variable from step 1 with `echo "NAME=$RUNNER_TEMP/gate-cache" >> "$GITHUB_ENV"`. (3) Safety: a pull request can read its own entries and the entries of `main`, and cannot write the entries of `main`; keep it so (do not add a workflow that writes caches from fork code with a wider token). The cache key of a step must cover every input of that step, including the runner image and tool versions; if a step's key misses the image name, add it, because a pass on one image is not a pass on another. A step with unknown inputs must always run. (4) Prove it with two controls. Hit control: rerun the same commit (`gh run rerun <run-id>`) and read the gate log; it prints how many steps came from the cache, and that count must be above 0. A new commit is not a hit control, because a step's key covers its input files. Miss control: push a commit that changes one input of one step (for example one Python file) and confirm that step runs again while a step with no changed input is restored. (5) Add the result and the rule "a cached pass needs the same inputs" to `docs/ci.md`. Never cache `private/` or any secret.
  - **Files**: .github/workflows/ci.yml; scripts/check.sh; tests/unit/test_gate_cache.py; docs/ci.md
  - **Hypothesis**: a rerun of a hosted run takes at most 70% of the time of the first run, because unchanged steps restore their pass.
  - **Measurement**: `gh run list --workflow ci.yml --branch <branch> --json databaseId,createdAt,updatedAt` for the first run and its rerun on 3 pull requests, plus the "from cache" line in each gate log.
  - **Success**: on 3 of 3 pull requests the rerun reuses at least one step and is at least 30% shorter; in the miss control the changed step runs again; `uv run pytest tests/unit/test_gate_cache.py -q` passes.
  - **Pivot**: if fewer than 2 steps ever hit the cache after one fix round, remove the cache step (it costs restore time) and record why in `docs/ci.md`.
  - **Anchor**: Forsgren, Humble & Kim 2018 (DORA); Mokhov, Mitchell & Peyton Jones 2018 ("Build systems à la carte", minimal rebuilds).

- [ ] Telemetry sink 1 of 2: let a company plugin send telemetry to its own log system (Splunk HEC or a file) instead of PostHog
  - **ID**: telemetry-plugin-sink
  - **Blocked**: prerequisite: telemetry-consent-key must land first
  - **Details**: A company may forbid a third-party analytics service and still want usage counts in its own log system. Today a plugin can only say `policy.telemetry: false`. This task adds a sink that only a plugin can set. Iron rule: this base repository must never hold a company name, an internal host, an index name, or a token; examples use `splunk.example.com`. Read `docs/plugins.md` (manifest and policy), `src/careerbrew/plugins.py` (`effective_policy`, manifest validation), `src/careerbrew/secrets.py` (secret references), `src/careerbrew/connectors.py` (`check_host`, `open_url`) and `src/careerbrew/telemetry.py` first. Steps. (1) Manifest. Add an optional block to `careerbrew-plugin.yaml` under `policy`: `telemetry_sink: {kind: posthog | splunk-hec | file | off, url: https://..., token: <secret reference>, index: <string>, sourcetype: <string>, path: <file path>, consent: ask | managed, error_logs: false}`. Validation at `plugin add` and `plugin verify`: `kind` is one of the four; `splunk-hec` needs `url` (`https` only; plain `http` is accepted only for a loopback host, `127.0.0.1`, `localhost` or `::1`, so tests and a local forwarder work and no token crosses a network in clear text) and `token`, and `token` must be a secret reference (`keychain:`, `op://`, `env:`), never a literal; `file` needs `path`, which must be absolute or start with `~` and must not be inside a cloud-synced folder (`machine.cloud_synced`); `posthog` and `off` take no `url`, `token` or `path`; `consent: managed` and `error_logs: true` are allowed only for `splunk-hec` and `file`. An invalid block refuses the install with a message that names the field. (2) Merge rule in `effective_policy`: strictest wins. Any plugin with `telemetry: false` or `kind: off` turns every send off. Two plugins with different non-off sinks: refuse both and say so (never send to two places, never pick one silently). (3) Sending. Put sink code in a new module `src/careerbrew/telemetry_sink.py` with one function per kind and one `deliver(events, policy)` entry; `telemetry.send()` calls it. The same allowlisted event objects go to every sink: a plugin sink gets no extra field. Splunk HEC body: one JSON object per event, `{"time": <epoch seconds>, "host": "careerbrew", "source": "careerbrew", "sourcetype": <sourcetype or "careerbrew:event">, "index": <index, only if set>, "event": {<allowlisted fields>, "install_id": <id>}}`, objects joined by newlines, POST to `<url>` (the plugin gives the full collector URL, for example `https://splunk.example.com:8088/services/collector/event`) with header `Authorization: Splunk <token>`. Send through the policy-aware opener `connectors.open_url` (it checks every redirect against `allowed_hosts`, refuses HTTPS to plain HTTP, and never lets a request with a token follow a redirect to another origin). It arrives with the pull request "close judge round findings" for the public release; if `rg -n 'def open_url' src/careerbrew/connectors.py` finds nothing, stop: that pull request must merge first. Never send the token with a bare `urllib.request.urlopen`. Resolve the token at send time with `secrets.resolve`; never store it, log it, or print it; the dry run shows `<token>`. File sink: append one JSON line per event to the path, create it with mode 600, and when it passes 5 MB rename it to `<path>.1` and start a new file; refuse the write when the file itself, its `<path>.1` rotation target, or any parent folder is a symlink (open with `O_NOFOLLOW` and check each parent), and when the resolved path is in a cloud-synced folder. With a plugin sink of kind `splunk-hec`, `file` or `off` set, nothing goes to PostHog (`kind: posthog` keeps the default service). (4) Consent. `consent: ask` keeps the user's question, with the destination named as "your organization's log system at <host>". `consent: managed` means the company decided: no question, sends are on, and `careerbrew telemetry status` and the first-run notice say who set it and where it goes; `careerbrew telemetry off` still turns it off for a user unless a later company policy field forbids that (do not add such a field now). `DO_NOT_TRACK=1` always wins. (5) `error_logs`: default false. When true, an event with `status: error` may also carry the exception class name (an id-shaped string, already allowed as `error`); never a message, a path, or a stack trace. (6) Status and dry run: `careerbrew telemetry status` prints the sink kind, the host or the path, the consent mode, and which plugin set it; `careerbrew telemetry send --dry-run` prints the exact body for the active sink. Update `careerbrew actions --json` parity if a command changes. (7) Tests first, with a local fake HEC server (a `ThreadingHTTPServer` on `127.0.0.1` port 0 inside a pytest fixture; copy the `redirector` fixture in `tests/unit/test_redirect_host_policy.py` if that file exists, else write the fixture new): the body shape and header are exact; the token never appears in stdout, the event log, or an error message (plant a canary token through `env:`); a literal token in the manifest refuses the install; `http://` to a host that is not loopback refuses; a host outside `allowed_hosts` sends nothing; a redirect to another origin sends nothing; two different sinks refuse; `kind: off` and `telemetry: false` send nothing; with a `splunk-hec`, `file` or `off` sink set, the PostHog fake receives zero requests; a failed send keeps the events queued and never fails a command; the file sink rotates, and refuses a symlinked file, a symlinked rotation target and a symlinked parent; a canary in any event text field never reaches any sink. (8) Docs: a "Company log sink" section in `docs/plugins.md` (the contract for plugin authors, with the example above), rows in `docs/privacy.md`, lines in `docs/corporate-machine.md` and `docs/observability.md`, a new user story with acceptance lines that name the tests, and one plain line in the corporate setup skill: "telemetry destination: `careerbrew telemetry status`".
  - **Files**: src/careerbrew/telemetry.py; src/careerbrew/telemetry_sink.py; src/careerbrew/plugins.py; src/careerbrew/cli.py; tests/unit/test_telemetry_sink.py; tests/unit/test_telemetry.py; docs/plugins.md; docs/privacy.md; docs/corporate-machine.md; docs/observability.md; docs/user-stories.md; skills/careerbrew-corporate-setup/SKILL.md
  - **Hypothesis**: a company that forbids third-party analytics can still see usage counts, with 0 events sent to PostHog from its machines and 0 content fields in its log system, because the plugin sink replaces the default sink and reuses the same allowlist.
