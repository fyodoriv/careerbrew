# Lessons

One dated line per run: what worked, what failed, why.
- 2026-10-19: first run over a full earlier deck -> 819 public cards, a few skipped. 11 parallel subagents by topic, each validating with publish --dry-run; publishing sequentially afterwards avoided write races. Failures: agents shared a scratchpad queue file and clobbered each other (give each a unique file); one agent got a wrong slice, leaving 80 cards for a second pass (always re-check explain-queue after publishing); the http lint was too strict for localhost code, now relaxed.
- 2026-10-19: review round. 8 independent reviewer subagents read all 819 public cards and corrected 16 (wrong facts such as tuple hashability and full-outer-join filters, outdated browser/React/kernel facts, bad estimates, one buggy hook). About 2% defects after generation: keep the review step after every large round. The skipped questions got private, encrypted explanations, so every card is explained.
- 2026-10-19: verification round. Gate now parses all 420 code examples (check-card-code.py); executing Python and JS examples found 4 real code defects that reviewers missed. Most skipped questions were public company knowledge (Amazon LPs, 'Why this company?') and became public cards. Lesson: skip only what names the user's employers, people, or own work, not every company name.
- 2026-10-19: line-by-line audit of all 838 public cards (12 auditors: every claim checked, ~340 examples run, leetcode solutions run on edge cases, all numbers recomputed). 50 cards corrected, plus 8 small fixes. Biggest catch: 16 generalized Amazon LP cards had garbled template answers, so generated batches need an audit before publish, not only after. Lint relaxed for XML namespace names.
